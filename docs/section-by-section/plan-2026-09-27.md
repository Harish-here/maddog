## Decisions (closed with the user)

- **D1 One check table for both turns.** `[section] — Diagnosed` shows the
  table and every verdict that fires; the user discusses; `[section] —
  Proposed` shows the text and the same table. Columns: Check · Looked at ·
  Result. Every row names what it examined — a bare `clean` is not allowed.
  Rows with findings sort first. Diagnosed ends rows in a verdict; Proposed
  ends rows in what changed. Correctness runs only in Diagnosed.
- **D2 Several verdicts per section.** At most one placement verdict
  (REMOVE, SPLIT, MERGE, MOVE) plus any wording verdicts (REPLACE, RESHAPE,
  COMPRESS, REWORD); KEEP stands alone; after SPLIT, wording verdicts apply
  to the halves. The `Also:` line goes. First-match stops.
- **D3 Ledger:** one row per closure, verdict column holds the set, main first.
- **D4 Ambiguity is its own axis,** after coherence, before correctness.
  Its check writes out the second reading of each sentence, or `none`.
  Verdict REWORD. Clarity keeps RESHAPE, COMPRESS, self-contradiction.
- **D5 Outside text only when named.** At Start the user may name files the
  target relies on; redundancy and term checks read them. Nothing else.
- **D6 Route:** run section-by-section on its own SKILL.md; the user closes
  every change. The user waives the author-agent gate for this change
  (CLAUDE.md routes load-bearing text there) — record the waiver in the
  commit and CHANGELOG. The release skill's independent reviewer still runs.
