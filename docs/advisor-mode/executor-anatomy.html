Anatomy of an executor

Every executor-* has the same body. What differs is which actions it may take and which laws guard them. Shown: executor-fast.

1 · TOOLS
What it can touch
set in the file header, not in prose

readwriteeditshell   The judge has no write or edit at all, and a guard script denies its shell write forms. A rule that must hold is built into the structure. Prose only says what an agent must not do; the tool list makes it impossible.

2 · DISPATCH
What a task must bring
it starts blank and cannot ask

Paths, error text, decisions already made, the output format, and a DONE-WHEN it can check itself. Anything missing is not a guess, it is a stop: return blocked and name the gap.

3 · ACTIONS → LAWS
Each action carries a law
laws forbid; two kinds means obeying both
EDIT · IMPLEMENT · OPERATEChesterton's fence, YAGNIChange, build, or stage only what was named. Anything nearby that looks wrong goes in NOTES, untouched.
RECOVEROne-way doors · Order of volatilityCapture pid, stack, log tail first, then remedy. Never force-push, rewrite history, or delete what the dispatch did not name.
TRANSFORMTotalityOne rule across many items: cover every fit, list every misfit, follow chains to the end. Stopping early fails.
GATEGoodhart's lawRun the test or lint exactly as named. Never touch inputs, thresholds, or snapshots. A red run is a result, not a stop.
REPRODUCEThe null hypothesisA bug claim starts NOT ESTABLISHED. Only a cited line or an on-demand failure moves it. No story without evidence.
executor-smart works the same way with eight modes: BUILD → conceptual integrity (Brooks) · PORT → characterization tests (Feathers) · AUTHOR → design by contract (Meyer) · DECOMPOSE → information hiding (Parnas) · FIX → null hypothesis · REVIEW → normalization of deviance (Vaughan) · DIAGNOSE → reproduce before you explain (Zeller) · CHOREOGRAPH → RAII (Stroustrup).
4 · ALWAYS
Laws that always hold
the same four in every executor

The andon cord. Two readings, two targets, or the tree contradicts the task: stop and say so. Picking the likelier one fails.

Faithful. Claim only what happened. Every skipped step and unfound item is written down, whatever STATUS says.

Distilled. Return the answer, not the material. Past the cap, file it and return the path. Never truncate silently.

Notes contract. Report, never interpret. RESULT carries what was asked. NOTES carries anomalies, never conclusions.

5 · RETURN
Exactly this shape
so the advisor can check it, not read it
STATUS: done | partial | blocked   partial whenever NOT DONE is not "none"
BLOCKED-ON: the gap or the door, only when blocked
RESULT: in the format the dispatch set
NOT DONE: every step skipped, item unfound, misfit left, or "none"
NOTES: anomalies seen, assumptions made, never conclusions

Laws are named after the engineering principle they enforce, so a reviewer can argue with the principle instead of the prose. The evals in evals/ check that each law actually fires on its pinned model.
